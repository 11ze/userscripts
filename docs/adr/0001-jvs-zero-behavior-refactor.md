# ADR-0001：拒绝 jvs.user.js 零行为且不利于代码阅读的修改

- 状态：已接受（2026-09-17，同日修订：把「不做零行为变化的结构收拢」修正为「不做零行为且不利于代码阅读的修改」——利于阅读的重构不在禁止之列）
- 背景：架构扫描（2026-09-17）提出把散在各特性函数里的新旧双版 DOM 判定（9 处）收拢成统一的「双版解析」层，实现并评审后整体撤销。

## 决策

不做既无行为价值又不利于代码阅读的修改。jvs.user.js 里的双版 DOM 查询继续留在各特性函数内，只有满足下面任一条件时才动结构：

1. 改动能修复真实缺陷或补上可测性（如候选 2 的监听器泄漏修复 + 纯函数化）；
2. 包装函数有多个调用点，删掉它会让调用点明显重复（过删除测试）；
3. 显著改善代码阅读（locality：同一特性的代码聚在一块，理解它不需要跨几百行跳转）。

## 理由

- 单调用点的包装函数（如当时的 `findSidebarMount`）删掉后内联回调用点零损失，是浅模块，过不了删除测试。
- 零行为变化意味着用户侧收益为零，但 jvs 改动按仓库规则必须在新旧双版线上实测——成本真实存在，收益必须落在代码可读性上，不能只是「看起来整齐」。
- 双版 DOM 判定散在特性内恰好和「改动时兼顾旧版」的心智模型耦合：动哪个特性就在哪看到双版分支，收拢反而拉远——那次撤销的问题正在于不利于阅读。

## 后果

- jvs.user.js 的双版判定保持分散；将来某处判定出现第三个调用点或产生真实 bug 时，可重开本决策。
- 按条件 3，特性聚拢重排（同源架构报告候选 3）这类纯移动但明显利于阅读的重构放行。
- 本 ADR 是 `docs/adr/` 的第一个文件；后续架构决策按需续编号。
