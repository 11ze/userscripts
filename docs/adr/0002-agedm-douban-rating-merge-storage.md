# agedm 豆瓣评分快照采用双存储 + 按条目合并

豆瓣评分快照（GM `agedmDoubanRatings`，形如 `{ [归一化搜索词]: {rating, name, at} }`）与屏蔽名单面临同样的脚本导出导入整包覆盖问题，但它是多部动漫的字典：两台设备各记各的番，ADR 0001 的整包裁决会让一台的记录整体顶掉另一台。决定沿用「GM 主存 + 当前域名 localStorage 镜像」的双写骨架，但合并语义按条目：启动时逐 key 比 `at` 新者胜（相同视为后读入的 GM 胜），合并结果回写两边。豆瓣页写豆瓣域镜像、agedm 页读写 agedm 域镜像，各自保护「该域最后一次见到的新数据」；GM 跨域共享，是两侧唯一的同步通道。

## Considered Options

- **GM 单存**：丢了逐部重查可恢复，但几百条快照逐部重查成本高。否决。
- **照搬 ADR 0001 整包裁决**：双设备互导时丢一台的条目，与双存储防丢动机相悖。否决，整包裁决保留给单一 list 数据（屏蔽名单）。

## Consequences

- 名字绑定产生的两条记录独立刷新，可能短暂分数不一——展示侧取 `at` 最新一条，下次搜索自愈。
- 弹窗决定表（`agedmRatingPromptChoices`）只存 GM：丢了只是多弹一次确认窗，无数据损失。
