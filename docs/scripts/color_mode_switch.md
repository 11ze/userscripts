# color_mode_switch.user.js 架构

- **iframe 闸门**：`@noframes` 只在顶层 frame 运行，跨 frame 写同一存储键的失步问题随之消除。
- **存储异常语义**：读异常出关闭、写异常返回 false，toggle 写失败即短路——内存态、存储态、视觉态三方一致。
- **CSS filter 约束**：子树无法脱离整页反转，媒体与自挂按钮只能二次反转抵消。
- **柔化与保色取舍**：使用较轻的端点压缩，避免亮页过灰，同时减少媒体高光和阴影损失；不加色温、饱和度或额外亮度调整。媒体使用逆序滤镜补偿，保住中间灰阶，输出黑白端点约为 RGB 6～249。高光、阴影和高饱和颜色仍受矩阵运算与色域裁切影响，不承诺无损。
- **媒体只抵消一次**：`picture` 是包装层，滤镜只挂内部图片；嵌套 SVG 共享最外层的处理。包装层和内容同时抵消会重新变成负片。
- **SVG 图标与图表**：按计算后的填色与描边识别中性色，固定黑白、灰色及解析为中性色的 `currentColor` 图标随页面变色；包含彩色绘制的图表保留媒体处理。图片、外部符号、渐变和非 RGB 颜色表达无法可靠判断，按媒体处理；不从颜色推断图标的业务用途。
- **原有媒体滤镜**：先执行站点滤镜，再补偿整页转换。采集时同步停用脚本样式、冻结媒体过渡并先恢复整批内联声明，防止读到脚本自身补偿、过渡插值中间值或污染 `filter:inherit`；采集末尾、解冻前逐元素回读 computed 落定终值，否则解冻边界会创建 `none`↔补偿链过渡（首屏负片渐回、关闭渐隐都是闪）。开启期间用内联 `!important` 保证补偿不被站点规则挡住；关闭时同样先冻结、清理落定后再撤冻结表。关闭后移除私有属性并恢复原值与优先级，保留站点后来写入的新值。观察新增内容、class/style/绘制属性与样式节点更新；外部变动在下一动画帧合并后全页重读一次，覆盖样式节点删除及兄弟选择器、`:has()` 的跨子树影响，跳过脚本自己的样式写入；关闭时取消待执行重算。后台标签页的更新随动画帧恢复而执行。外部样式表加载后也重读。纯 CSS 动画、伪类状态及 CSSOM `insertRule` 引起的滤镜变化不在跟踪范围。
- **全屏边界**：全屏内容进入顶层后脱离根滤镜，必须撤掉全屏元素及其媒体后代的补偿，只保留站点原有效果；退出全屏后重新采集并恢复补偿。全屏容器本身的原滤镜也需保存与恢复。
- **背景图取舍**：不对背景图容器整体抵消反转，否则正文也会恢复原配色，且内联与样式表背景得到不同结果。背景图跟随页面反转；轻量滤镜方案无法通用地只保留容器背景图原色。
- **逃生舱边界**：仅 `.reverse-color-mode-ignore`，只取消媒体补偿并保留站点原滤镜；禁用 data-theme 之类的属性选择器——特异性高于 `html`，会把挂在 `<html>` 上的站点（GitHub、Docusaurus）整页反转反杀成 filter:none，图片仍负片。
- **图标分家**：按钮图标 fill `#fff`（底 `#000`，黑底白月）；`@icon` currentColor（底是油猴浅色管理面板，回落黑）。img 加载的 SVG 是独立文档，currentColor 一律回落黑色——一份 SVG 无法同时满足两处，两份 base64 人肉同步，形状一致性（剥 fill 后逐字节一致）由测试锁定。v0.1.1 曾一刀切 `#fff` 致 @icon 面板不可见。
- **按钮黑底白月（定稿「墨盘」）**：按钮只在反转开启时显示（关闭态 `display:none`）；主场景暗转亮，反转后的亮页上黑底白月对比度最高。黑底唯一隐身场景是亮转暗的反转后暗页——罕用方向，v0.1.3 起用发丝描边 `rgba(255,255,255,.22)` 勾出边界兜底，另配轻阴影防反转后亮页上悬空。
- **常态全不透明**：v0.1.2 常态 0.7 透明度在 v0.1.3 移除——0.7 会把发丝描边压没，暗页存活失效。
- **hover 三联动**：容器监听 mouseenter/mouseleave（不冒泡，mouseover 会在容器与子元素间连击抖动），经闭包同时作用于按钮（上浮 2px、描边变亮）与 tooltip（浮出「还原配色」），容器自身无样式变化。
- **tooltip 挂 button 内**：`<span>` 绝对定位探出按钮左侧。挂按钮内两个原因：关闭态 `display:none` 级联隐藏无需同步显隐；随按钮 hover 位移一起动。按钮需 `position:relative`（定位锚点）+ `overflow:visible`（防站点样式裁切探出部分）；tooltip `pointerEvents:none` 不参与 hover。暗页上黑底气泡不可见边界，自带描边与按钮同理。
- **图标防站点样式污染**：按钮图标是 `<img>`，会被站点全局 img 样式（border/outline/padding/background）命中打出方框——黑底时代深色边框看不出来，2026-10-15 浅色图标期暴露后修复。图标样式必须内联重置这四项。
- **图标反转层数**：切换容器在二次反转组内，容器内 img 若再叠媒体补偿会形成三层反转，导致黑底黑字。容器内 img 必须只保留站点原滤镜。
- **document-start 时序**：样式与菜单命令在 document-start 即生效防加载期闪白；按钮挂载等 DOMContentLoaded（此前 body 未就绪）。
- **补偿链自捕获（2026-11-11 weekly.tw93.fun 三轮排查定案：采集末尾落定根治过渡创建；冻结表与链剥离保留为纵深）**：真根因是站点给 `.card-cover` 等媒体设了 `transition: filter`（0.12s），叠加 CSS 过渡的前置样式语义——前置样式取上一次样式变更事件的计算值，`getComputedStyle` 会强制一次样式变更事件并把当时的计算值记账。采集周期"恢复内联→读 computed→重挂模板"里，读原值时（反转表停用、模板已摘）引擎把 `none` 记为最后计算值；重挂模板的写入尚未重算，解冻边界（冻结表撤下、站点 0.12s 过渡生效）`none ≠ 补偿链` 创建过渡——首屏从恒等（负片）渐回补偿即"闪三四下"（每解析波各闪一次），无后续重算的折叠下方元素停在恒等负片直到滚动/hover（用户首轮症状同源）。关闭方向对称：撤表后在冻结区外清内联补偿，`补偿链 → none` 过渡照样创建（关闭闪，实测 18 图共 54 个过渡事件）。单独冻结只把过渡创建从采集内推迟到解冻边界：未冻结时该过渡立即运行，后续采集把飞行中插值读成原值（第一轮的链污染、第二轮的残余闪烁同源）。落定根治：采集末尾、解冻前对每个采集元素再读一次 computed，把终值落定为最后记账的计算值，解冻前后一致不创建过渡；关闭时先冻结、清内联并落定、再撤冻结表。引擎按元素惰性重算，读单个元素不落定其余脏元素，必须逐元素回读。开启反转时随反转表注入采集冻结表（`:is(img, video, iframe, canvas, svg, :fullscreen):not(#…)` → `transition: none !important`，ID 位特异性压过 Tailwind `.!transition` 这类 class 级 important 过渡），采集窗口内恢复、读取、重挂、落定全程禁过渡；非采集期间禁用，站点自身过渡不受影响，关闭时随反转表一并移除。第一轮排查的"外部重放者"系误判：无脚本时页面加载后零变动（全量 MutationObserver 实测），所谓"写回缓存 style"是脚本自身的恢复/重挂写入，"6 位舍入/漂移链值"实为过渡插值快照（99.9% 插值即 `contrast(1.05259) hue-rotate(179.867deg) invert(0.999261)`）。剥离层继续保留：识别并剥离内联与 computed 尾部重复的补偿链签名（有序三元组 contrast≈1.0526→hue-rotate≈180deg→invert≈1，容差 0.002 / 1deg / 0.002），站点暗色常用的 `invert(1) hue-rotate(180deg)` 顺序不同不会误剥，含 `var(` 的模板字面量不进剥离。`brightness(0.94)` 系站点 hover 伪类规则（`.card-content:hover .card-cover`），采集瞬间悬停仍会采到 hover 态——伪类捕获为已知边界。排查坑：Tampermonkey 沙箱作用域内，脚本调用的 `getComputedStyle`/`requestAnimationFrame` 不经过页面控制台的全局替换——控制台探针对用户脚本的读取/帧计数全盲，勿据此断言脚本空闲；插值中间值可用 rAF 采样 computed 逐帧还原（0.12s 轨迹与百分比吻合即实锤）；断言"零过渡事件"必须先落帧——`transitionrun` 在渲染时机派发，微任务里数事件恒为零（假阴性）；在引擎属性（如 `HTMLStyleElement.prototype.disabled`）上设陷阱必须透传原 setter，否则被观察机制本身失效，数据全错；对真实站点复现时，保存的 HTML 用 document-start 注入跑，合成页缺级联与加载波次可能复现不出。

验证：`node --test tests/color_mode_switch.test.mjs`。

浏览器回归：在仓库根目录运行 `python3 -m http.server 4312 --bind 127.0.0.1`，打开 `http://127.0.0.1:4312/tests/color-mode-switch.browser.html`，点击「运行媒体验证」，等到全部通过后再点击「运行全屏验证」。页面加载当前脚本，使用内存存储；检查真实级联、观察器调度、媒体豁免、全屏进出与原滤镜恢复。Node 桩不执行完整 CSS 选择器与级联，不能替代该验证。

性能复测：同一服务打开 `http://127.0.0.1:4312/tests/color-mode-switch.perf.html`，点击「运行验证」，刷新后重复。固定 1000 张图片和 20 批文本更新，输出读取次数、回调与动画帧累计耗时及长任务次数；比较修改前后应使用同一浏览器和前台标签页，耗时不作为跨机器的固定断言。v0.1.6 动画帧合并的前后实测（同一 Chrome for Testing、前台标签页、各 5 轮）：单轮计算样式读取 20020 → 4004 次（20 批变动合并为约 4 次全页重读），回调累计耗时约 53ms → 13.5ms，两侧均无 50ms 以上长任务。

视觉验收：启动 `python3 -m http.server 4311 --directory designs`，打开 `http://localhost:4311/color-mode-switch/index.html`。两个画板只展示改进后的亮色、暗色，都运行实际脚本。检查正文、图片、固定白色图标与彩色图表。展开「图片效果与视频」，确认灰度图片未恢复彩色，进入视频全屏后色条无额外反转，退出后恢复页面转换。输入文字、滚动并点击月亮，确认滤镜、私有属性和单色标记均已清理。用「重新预览」恢复两个画板。
