# jvs.user.js 架构

只记代码推不出的约束、否决与坑；机制看源码分节注释与测试。版本号锚定 git 溯源。

- **新旧双版**：站点有新版（qicong-edf）与旧版（jyy-dev）两套环境，DOM 结构不同；改动须两版兼顾并在两版实测。
- **操作队列**：probe 纯读、apply 消费 probe 采到的数据不二次读取；probe 键不变时跳过 apply（probe 返回 `{ key, payload }` 时 apply 直接收 payload）。
- **定义顺序**：operations 数组与 setInterval 须放在全部定义之后——TDZ 前科 v0.8.6（局部遮蔽全局同名函数真机崩过）；测试钩子块仅 `getStyles` 用箭头惰性引用其后定义的 JVS_STYLES，其余登记的 const 须定义在钩子块之前。
- **设计器类型**：`getTabType` 须设计器头部与页签文本同时满足——否则旧版非设计页残留的「逻辑设计」页签被误匹配。
- **旧版节点展开名称**：只压缩 `.ef-node-text` 行高并框内垂直居中，节点框/`.top`/连线锚点零改动——`height: auto` 会让节点形态重算、锚点错位，已被用户截图否决。
- **新版节点形态保持原生**：节点形态全部保持原生；`ze-typed` 命中描边（v0.7.31 引入）已于 v0.8.12 整体撤销，勿再加回。脚本只动连线观感：
  - 连线：stroke 与 stroke-width 由应用按状态控制，覆盖会压掉变色；success 绿虚线是日志回放动画，绝不能碰。连线规则 `:not` 排除的是应用状态类词表快照——应用加新状态类须回来补，否则新状态线被压平成实线。
  - 端点：纯 CSS 改观感不碰坐标，连线数据零影响。
  - 入边箭头：原生扎进节点 4px 的位置被用户否决；细杆 + V 形尖角方案被用户否决，勿改回。`:not(.jtk-droppable)` 隔离旧版（旧版节点类名包含新版选择器）。
  - 教训：给 `.jvs-rule-node` 本体加任何定位会激活 inline 画布坐标致节点飞偏（styles 测试锁节点本体零规则块）；框高不可动——变高让 Butterfly 锚点按渲染高算线点、连线错位且污染保存的 `breakPoints`（后端按 36px 固定模型渲染）。
- **表单设计组件名常显**：站点 hover 规则直接命中 `.type-name` 本体，加类拦不住，须 `!important` 盖回；覆盖挂在脚本加的类上，未加类的组件不受影响。
- **应用中心星标**：星标按钮不走 `createButton`（皮肤类与星标透明形态冲突）；渲染与点击均现读存储（多标签页同开不互相覆盖）。
- **只看星标过滤**：JS 只产出一个事实（`body` class）——卡片显隐、整组隐藏、空态提示全由 CSS `:has()` 驱动，按钮激活态也由 body class 派生。坑：空态提示须等第一张卡出现后插进其父级（往容器 prepend 会顶到筛选行上方，曾致 bug）；按钮字号须显式写（旧版挂载点继承值 12px，inherit 拿不到搜索框层的 14px）。
- **应用中心侧边栏收起**：与只看星标同一范式（body class + CSS 驱动）。坑：展开态 left 每 tick 按侧边栏右缘 rect 校准；收起态 `display:none` 后 rect 归零不可读，只能取固定值。
- **应用中心地址栏同步**：用 `replaceState` 统一到 `#/wel/index`——不触发 hashchange/vue-router，衔接刷新后 `wel/index` 自动点击；轮询幂等，旧版天然不处理。
- **模式读写分离**：`currentMode` 是读取统一入口——历史映射优先，采集值变才落库（同值不重写）；`collectAppName` 是写一次语义，应用改名不回写。
- **幂等注入**：`ensureInjected` 是按钮判重注入统一出口，后续注入类按钮优先走此模块；mount 返回 null 为「移除后可不建」语义（复制设计名的 use 图标门依赖此）。
- **日志查询**：`latestLogWhere` 是唯一内核，其余查询是单行包装；无跨 tick 缓存，同一 tick 内多次查询由调用方解析一次传入复用。
- **日志弹窗**：document 外点关闭监听器注册/摘除必须成对——历史实现 toggle 路径只删弹窗不摘监听器，每次泄漏一个，多活到下一次任意点击才自愈。
- **日志按钮模式换色**：模式前缀与「日志」同字号同色、6px 间距替代全角「｜」（前缀缩字号、黑色前缀两方案已被用户否决，勿改回）；模式变化走容器 remove+重建、不播 transition；表格行色与按钮换色同出自 `MODE_COLORS` 单一事实源。
- **设置栏按钮间距**：「测试」按钮外包两层 span、自身盒内 margin-left 溢出会吃掉相邻间距——实测 22px 视觉缝才追平左缝。
- **画布滚轮平移**：
  - 全走 Butterfly `canvas.move` API——旧实现 CSS 硬怼 wrapper/minimap left/top 是死路（坐标系不知情、与左键拖拽打架、minimap 只能魔法系数单向模拟）。
  - 重建带回平移：应用重建画布后视口从 [0,0] 开始，probe 探测到实例更换即带回销毁前平移（一个 tick 空窗画布短暂闪回，可接受；零平移、首见画布不恢复）。
  - 切换画布清记录：主/循环切换同为重建但身份变了——直接作废平移记录，切回也不重放（用户否决了「切画布也保留平移」）。身份选择器取不到时退化为不清记录，方向安全。
  - 待挂键带递增代数：一个 tick 内连续重建时，裸键相同会让调度器误判无变化而永远跳过 apply，监听丢失死锁（seen 只有 apply 才推进）；带代数后键互不相同，apply 必然触发。
  - 平移后同步宿主 `offsetXY`：拖入新组件的落点只认宿主组件 data 的 `offsetXY` 字段，该字段应用只在原生左键拖拽结束时同步——脚本 wheel/restore 不经那条路径，不同步则落点按旧平移量错位（滚 600 拖组件直接飞出视口）。
